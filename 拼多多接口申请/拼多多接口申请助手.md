# 拼多多接口申请助手（商家后台系统 · 自用型）

> **官方入驻文档**：[拼多多开放平台 · 入驻流程](https://open.pinduoduo.com/application/document/browse?idStr=04DD98845AD2977D)  
> **文档用途**：指导友联以「拼多多商家 + 商家后台系统」身份完成开放平台入驻、应用创建、店铺授权与接口对接。  
> **适用对象**：操作员、技术组、海婷审核材料时使用。  
> **更新时间**：2026-07-07

## 老板版 8 行结论（先看这个）

1. 拼多多**不是**谁都能开 API——须以「拼多多商家」身份入驻，且**必须有招商小二对接并审批**。  
2. 应用类型选 **商家后台系统**（自用 ERP/OMS），不是服务商、不是多多进宝。  
3. **初始最多 6 个店铺授权**：商家后台可配 **5 个店铺** + **原有主账号 1 个**；超出须找**店铺对接的招商小二**申请提额。  
4. **所有授权店铺必须属于同一实际控制主体**（同一公司/同一实控人），跨主体不可混绑。  
5. 授权、登录、OAuth 必须用**店铺主账号**，子账号不能完成授权。  
6. 创建应用时须填写**招商小二花名**，小二约 **1 个工作日内**收到审批单。  
7. 审核通过后，在「应用详情 → 授权管理」配置店铺，获取 `access_token` 后方可调接口。  
8. 友联侧待建 `PddClient`（MD5 签名，无官方 Python SDK）；token 有效期以控制台为准，须做缓存与续期。

## 助手定位

你是「拼多多接口申请助手」，服务友联申请拼多多开放平台 **商家后台系统** API。你的目标：

- 把入驻流程标准化（注册 → 认证 → 建应用 → 小二审批 → 店铺授权 → token）  
- 核对材料与主体一致性，减少驳回  
- 回答「能绑几家店」「怎么加授权数」「主体不一致怎么办」  
- 对齐友联 AI 中台 / union-agent 对接计划（订单、商品、发货、售后）

## 1. 适用范围与核心限制

| 项 | 规则 |
|----|------|
| 应用类型 | **商家后台系统**（自用型，给自有店铺用） |
| 开发者角色 | **拼多多商家**（须经招商小二认证，非普通企业开发者） |

| 主体要求 | 所有店铺须属**同一实际控制主体** |
| 授权账号 | 必须用**店铺主账号**登录授权，**禁止子账号** |
| 对外服务 | 不可上架服务市场、不可给他人店铺用、不可转让 client_id |

## 2. 入驻前置条件（必须全部满足）

### 2.1 店铺与账号

- [ ] 已在拼多多商家后台（[mms.pinduoduo.com](https://mms.pinduoduo.com)）完成开店，店铺**审核通过**  
- [ ] 已缴纳对应类目**足额保证金**  
- [ ] 使用**店铺主账号**操作开放平台与授权（非子账号）  
- [ ] 店铺状态正常（非冻结、非清退）

### 2.2 招商小二（硬性门槛）

- [ ] 登录商家后台 → **店铺管理 → 店铺信息**，确认有**招商小二花名**  
- [ ] 若无小二信息：先联系**类目小二**或**其他招商小二**沟通对接意向  
- [ ] **无任何招商小二愿意对接** → 暂不满足「拼多多商家」开放平台入驻条件，**不要硬提申请**

> 旺店通等第三方文档亦强调：该申请**必须经店铺招商小二审批**；无小二同意则不符合自研商家系统入驻要求。

### 2.3 主体一致性

以下主体原则上须一致或可证明**同一实际控制主体**：

1. 开放平台入驻企业 / 开发者认证主体  
2. 软件著作权登记主体（如有）  
3. 拟授权店铺所属主体  

**多店绑定**：所有店铺必须属于**同一实际控制主体**。主体不一致时需提前准备天眼查/企查查等关联证明，并预期人工审核。

### 2.4 自研能力（审核常见要求）

- 国家软件著作权（电商 OMS/ERP 类，名称与系统说明一致）  
- 系统功能说明书（功能模块、API 调用说明、架构图、截图、源码片段）  
- 能证明真实业务闭环：订单处理、发货回传、商品/库存、售后等（非只读壳系统）

## 3. 入驻全流程（7 步）

### 步骤 1：注册开放平台账号

1. 打开 [拼多多开放平台](https://open.pinduoduo.com) → **注册**  
2. 完成手机号验证等基础注册

### 步骤 2：选择开发者角色并提交资质

1. 登录控制台 → 选择开发者角色  
2. 角色选 **「拼多多商家」**（非「商家服务商」「平台合作伙伴」等）  
3. 按页面上传企业资质，信息与营业执照**完全一致**  
4. 等待资质审核（周期以平台为准，预留 **3~10 个工作日**）

### 步骤 3：确认招商小二花名

1. 商家后台：**店铺管理 → 店铺信息** → 记录**招商小二花名**  
2. 入驻前与小二沟通自研系统对接意向，避免审批单无人处理

### 步骤 4：创建应用（商家后台系统）

1. 控制台 → **应用列表 → 创建应用**  
2. 应用类型选 **「商家后台系统」**  
3. 填写应用名称、简介、回调地址等（以页面为准）  
4. **必填：对接的招商小二花名**（对应小二约 1 个工作日内收到审批单）  
5. 提交应用信息审核，等待**招商小二审批**

> 注意：控制台出现「入驻开放平台成功」仅表示**开发者入驻成功**，不等于「商家后台系统」应用资质已通过，需区分两类审核状态。

### 步骤 5：店铺授权（初始 ≤ 6 家）

审核通过后：

1. 进入 **应用详情 → 授权管理**  
2. 配置需对接的店铺账号（初始：**最多 5 个店铺 + 主账号**，合计 **6 个**）  
3. 跳转授权页时，用**各店铺主账号**登录并完成「授权并登录」  
4. 授权完成后，通过 OAuth 或接口换取各店 `access_token`

**OAuth 授权入口（商家）**：

- PC：`https://mms.pinduoduo.com/open.html`  
- 获取 token：`https://open-api.pinduoduo.com/oauth/token`

### 步骤 6：申请接口权限包

在应用内按业务申请权限（名称以控制台为准），友联典型需求：

| 业务 | 常见权限方向 |
|------|----------------|
| 订单 | 订单查询、订单详情、发货状态 |
| 商品 | 商品发布/编辑、SKU、库存 |
| 物流 | ERP 打单、物流发货、电子面单 |
| 售后 | 退款/退货处理 |

> 客服聊天记录：**无官方开放 API**（知识库 E18 已记录）。  
> 仅退款 ≤200 元等规则以平台现行政策为准，接口无法拦截。

### 步骤 7：技术对接与上线

1. 实现签名客户端（`client_id` + `client_secret`，**MD5 签名**，无官方 Python SDK）  
2. 按店铺缓存 `access_token`，实现自动刷新（有效期以控制台文档为准）  
3. 先打通 **1 家店** 最小闭环（拉单 → 发货回传），再扩展至多店  
4. 对接目标代码仓：`union-agent`（后端 `PddClient`）

## 4. 店铺授权数量规则（重点）

### 4.1 初始额度

```
商家后台系统 初始可配置店铺数
├── 可新增授权店铺：5 个
├── 原有主账号店铺：1 个
└── 合计上限：6 个店铺
```

### 4.2 如何提升授权数量

| 场景 | 做法 |
|------|------|
| 需要绑定第 7 家及以上店铺 | 联系**该店铺对接的招商小二**发起提额申请 |
| 多店但不同主体 | **不支持**；须同一实际控制主体 |
| 集团多法人多店 | 需与小二沟通是否可认定为同一实控主体，并备关联证明 |

**对外统一口径**：  
「拼多多商家后台系统默认 6 店额度；更多店铺须招商小二审批，且所有店须同一实控主体。」

## 6. access_token 与多店管理

| 规则 | 说明 |
|------|------|
| 获取方式 | OAuth2.0 授权码模式，或控制台授权管理页引导 |
| 多店 | 每个 `shop_id` 对应独立 `access_token` |
| 主账号 | 仅主账号可授权；授权后可在商家后台取消授权 |
| 缓存建议 | 本地持久化 token，到期前刷新，避免每次请求重新 OAuth |
| 有效期 | **以开放平台当前文档为准**（对接时务必在控制台核对，勿沿用过期口径） |

申请「商家后台系统」时，系统定位建议与友联现有资产对齐：

| 友联能力 | 拼多多侧诉求 |
|----------|----------------|

## 8. 常见问题（FAQ）

### Q1：为什么必须找招商小二？

拼多多将「拼多多商家」开放能力限定给**经小二认证的品牌商/大商家**。无小二对接则无法完成商家身份入驻与应用审批。

### Q2：初始能绑几家店？

**6 家**：5 个可配置店铺 + 1 个主账号店铺。更多须小二申请提额。

### Q3：不同公司的店能绑在同一个应用吗？

**不行。** 所有店铺须属于**同一实际控制主体**。否则应分别评估或走合规关联证明。

### Q4：子账号能授权吗？

**不能。** 授权页须**店铺主账号**登录后点击「授权并登录」。

### Q5：和抖店/淘宝申请有什么区别？

| 维度 | 拼多多 | 抖店/淘宝 |
|------|--------|-----------|
| 准入 | **强依赖招商小二** | 资质 + 平台审核为主 |
| 初始多店 | 硬上限 6，提额找小二 | 多店授权流程相对明确 |
| 客服 API | **基本不开放** | 部分平台有部分能力 |
| SDK | **无官方 Python SDK** | 抖店有 SDK |
| 签名 | MD5 | 各平台不同 |

### Q6：入驻成功但调不了接口？

检查：① 应用是否「商家后台系统」且小二已批；② 目标店是否已授权；③ `access_token` 是否对应该 `shop_id`；④ 权限包是否已开通。

## 9. 失败高风险点（提交前自查）

1. 无招商小二或花名填错 → 审批单无人处理 / 直接驳回  
2. 用子账号做授权 → 授权失败或 token 无效  
3. 试图绑定超过 6 家店且未找小二提额  
4. 绑定店铺非同一实控主体  
5. 软著与系统功能说明书不一致（空壳系统）  
6. 把「开发者入驻成功」误认为「应用+权限已全部开通」  
7. 未实现 token 缓存，生产环境频繁掉授权

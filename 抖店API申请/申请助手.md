## 第一篇 老板版结论

1. 抖店自研系统 API 仅面向**官方旗舰店**开放，店铺类型不对直接卡死。
2. 软著必须是国家版权局颁发的电商 OMS/ERP/WMS/CRM 等管理系统类软著，著作权人需与店铺、开发者实名认证一致。
3. 除软著外还要**商家研发系统支出证明**，可提供采购服务器资源等费用截图或合同文件，材料门槛高于淘宝。
4. 一个公司主体 + 一个软著主体 = 只能创建 1 个商家后台系统应用。
5. 同集团多店可走多店授权，但不能给无关联第三方公司店铺用。
6. APPKEY 不可转让、不可上架服务市场、不可代他人使用。
7. 非自研/虚假材料/长期零调用零绑店 → 清退/封禁（30天/90天/永久）。
8. 申请策略：先 1 家店打通最小闭环，再扩多店授权。
9. API 权限策略：店铺、素材中心、商品、订单、库存、售后退款、物流发货、电子面单、账单、精选联盟、保险、商户登录风险、飞鸽、短视频共 14 类 API 必须申请；短信 API 不申请。
10. 工具 API 原则上不作为业务权限申请，仅保留 Token、授权查询等必要接入能力；其他未列明专项 API 按明确业务需求单独评估。
11. API 调用需付费：基础和增值收费 API 均按调用量计费；抖店云内单价约为云外的 1/10，必须预充值并做好余额预警。
12. 材料一次性备齐再提交，减少驳回往返。
13. **一句话：真自研 + 真店铺 + 真关联 + 真使用，四真缺一不可。**

## 第二篇 店铺类型规范

> 来源：抖店《店铺类型规范》（2026-04-27 修订生效）

### 2.1 店铺类型总览（7 类）

| 店铺类型 | 入驻主体 | 数量限制 | 奥莱店 |
|---|---|---|---|
| 官方旗舰店 | 企业 | 1品牌1家；同主体含旗舰店≤5家 | 不支持 |
| 旗舰店 | 企业 | 1品牌1类目1家；同主体含官旗≤5家 | 平台定邀 |
| 专卖店 | 企业 | 同主体≤5家 | 平台定邀 |
| 专营店 | 企业 | 同主体≤5家 | 平台定邀 |
| 企业店 | 企业 | 同主体≤5家 | 不支持 |
| 个体店 | 个体工商户 | 同主体≤3家 | 不支持 |
| 个人店 | 自然人 | 同身份证1家 | 不支持 |

### 2.2 官方旗舰店（重点：自研系统准入前提）

- 定位：品牌官方唯一权威店铺（直营/独家授权）
- 品牌经营：可经营自有或授权品牌，多品牌需同一商标持有人
- 商标要求：自有品牌支持 R 标或符合条件 TM 标；授权品牌需 R 标
- 授权要求：境内一级独占；境外一/二级独占

### 2.3 旗舰店

- 定位：知名/潜力品牌专业店铺
- 商标与授权：与官方旗舰店接近（潜力品牌可中品牌力）

### 2.4 专卖店

- 定位：知名/潜力/成长品牌分销渠道店
- 商标要求：R 标或符合条件 TM 标
- 授权要求：境内一/二级独占；境外一/二/三级独占

### 2.5 专营店

- 定位：多品牌集合经营店铺（2 个及以上品牌）
- 可跨多个商标持有人品牌
- 授权要求：境内一/二/三级独占；境外一/二/三/四级独占

### 2.6 企业店

- 定位：企业主体普通经营店
- 可经营 1 个及以上自有/授权品牌，可跨商标持有人
- 部分品牌需满足《品牌限售细则》

### 2.7 个体店 / 个人店

- 个体店：个体工商户，同主体≤3家
- 个人店：自然人，同身份证仅1家
- 部分品牌禁止经营

### 2.8 店铺类型变更

变更需满足：

1. 品牌力满足目标类型要求
2. 品牌资质满足目标类型要求
3. 店铺命名包含目标类型对应品牌名
4. 绑定的官方账号或授权号满足目标要求
5. 非旗舰店升级旗舰店时：近 30 日体验分 >= 同行均值 + 入驻≥30 天

变更入口：

- 企业主体：`店铺信息设置 -> 店铺设置 -> 店铺升级`
- 个体店/个人店：需先做主体资质升级 `店铺信息设置 -> 店铺资质 -> 主体变更`
- 审核时效：1~3 个工作日

### 2.9 店铺处置措施

不符合要求或出现侵权/售假/虚构功效/抽检不合格/负面舆情等，平台可降级、改名、屏蔽。

### 2.10 附则

- 首次生效：2019-12-31
- 最新修订生效：2026-04-27
- 生效前行为适用当时规则，生效后适用本规则

## 第三篇 开发者入驻流程

> 来源：抖店《入驻流程》（2022-06-28）

### 3.1 注册开发者账号

1. 填写手机号码
2. 输入短信验证码（支持 4 位）
3. 提交注册

### 3.2 提交认证信息

**信息填写规范：**

- 所有信息必须真实且与实际一致
- 以下信息需与上传证件保持一致：
  - 企业名称、注册地址、统一社会信用代码
  - 营业期限、法人姓名、证件号码、证件有效期

**资质上传规范：**

- 图片需清晰，边框完整
- 复印件必须加盖公章

**审核周期：**

- 平台通常在 **10 个工作日内**完成认证审核
- 不通过需按驳回意见重新提交

### 3.3 认证与应用创建关系

- 仅当认证审核通过后，才可创建应用
- 未完成认证时，应用创建入口受限

### 3.4 应用类型选择

| 类型 | 适用对象 | 说明 |
|---|---|---|
| 自用型应用 | 商家自身具备开发能力 | 定制功能或数据同步，仅自有店铺使用 |
| 工具型应用 | 具备团队与行业经验的服务商 | 上架服务市场，服务多个商家 |

### 3.5 入驻前检查清单

- [ ] 已完成开发者账号注册
- [ ] 企业信息与证件信息逐项核对一致
- [ ] 资质图片清晰、盖章合规
- [ ] 预留至少 10 个工作日审核周期
- [ ] 明确应用类型（自用型 / 工具型）

## 第四篇 商家后台系统类目管理规范

> 来源：抖店《商家后台系统类目管理规范》（2025-12-15 生效）

### 4.1 类目定义

**一级类目（电商商家自研）：** 品牌商家将自有系统（ERP/OMS）与平台对接，支撑自身业务。

**二级类目核心功能（商家后台系统）：**

- 商品管理、店铺装修、库存同步、订单同步
- 电子面单、订单发货、飞鸽客服工具
- 售后管理、订单开票、财务对账

### 4.2 入驻要求（2025版，7 项准入）

| 准入项 | 要求 |
|---|---|
| 企业主体 | 仅企业，不支持个体工商户和个人 |
| 店铺类型 | **仅面向"官方旗舰店"开放** |
| 主体关系 | 店铺主体与开发者需同一公司或公开可查关联；不支持授权书/员工证明等 |
| 软件著作权 | 必须为国家版权局颁发的电商 OMS/ERP/WMS/CRM 等管理系统类软著；著作权人需与店铺、开发者实名认证一致；登记号与证书图片信息匹配；可在中国版权保护中心官网查询；一个软著号只绑一个主体；不支持电子版权/易版权等第三方认证 |
| 系统功能说明书 | 按模板提交，覆盖功能、架构、接口调用 |
| 研发支出证明 | 必须提供商家研发系统支出证明，可提交采购服务器资源等费用截图或合同文件；材料需能体现公司主体信息 |
| 对接业务方向 | 明确说明对接模块（订单/商品/发货等） |

**软著核验入口：** `https://register.ccopyright.com.cn/query.html`

### 4.3 运营规范

- 应用仅可供自身店铺使用，不得绑定他人店铺
- APPKEY 不得转让
- 一个公司主体仅可创建 1 个商家后台系统应用
- 一个软著主体仅可创建 1 个商家后台系统应用
- 同集团多店可通过控制台申请多店授权
- 三方代开发场景应由技术服务商入驻服务市场提供服务

### 4.4 平台处罚规则

出现以下情形，平台可删除 APPKEY 并收回接入资质：

1. 接入系统并非商家自研
2. 应用提供给他人店铺使用
3. APPKEY 转让他人
4. 多次提交无效/虚假信息 → 30 天 / 90 天 / 长期封禁
5. 入驻信息过期（身份证/企业状态/软著状态）
6. 近 3 个月零调用 + 零绑店
7. 服务商协助无研发能力商家违规申请 → 追责处罚或清退

### 4.5 违规管理

违反平台协议或规则，平台可对应用和资质执行冻结、封禁、清退。

### 4.6 附则

- 生效时间：2025-12-15
- 生效前行为适用当时规则，生效后适用本规范

## 第五篇 API 申请与接入实操

> 来源：抖店《自用型应用入驻指南》（2024-10-25）

### 5.1 适用范围与核心限制

- 仅适用于商家后台系统（自用型应用），只能给自有店铺使用
- 应用不可提供给他人店铺，不可在服务市场发布
- APPKEY / app_id 不可转让
- 同一公司主体仅可创建 1 个应用
- 同集团多店铺需走多店铺绑定授权

### 5.2 申请前自检

**主体一致性（三者需一致或强关联）：**

1. 软件著作权主体
2. 开发者账号认证主体
3. 授权店铺主体

**证明材料：**

- 国家版权局颁发的软件著作权证书扫描件或照片（著作权人、登记号、证书图片信息需匹配，并可在中国版权保护中心官网查询）
- 系统功能说明书（含 API 调用信息、系统架构、功能截图、源代码片段）
- 商家研发系统支出证明（采购服务器资源等费用截图或合同文件，需体现公司主体信息）
- 授权店铺信息（正常营业状态）

### 5.3 材料清单

| 材料 | 要求 |
|---|---|
| 系统功能说明书 | 体现 API 调用信息、系统架构、功能截图、软著、源代码片段 |
| 软件著作权 | 国家版权局颁发的电商 OMS/ERP/WMS/CRM 等管理系统类软著扫描件或照片；著作权人需与店铺、开发者实名认证一致；登记号与证书图片信息匹配；可在中国版权保护中心官网查询；不接受易版权等第三方电子版权认证、非管理系统类 APP 软著、授权书替代或 PS/造假材料 |
| 商家研发系统支出证明 | 采购服务器资源等费用截图或合同文件；材料需能体现公司主体信息 |
| 绑定店铺 | 授权店铺名称，店铺需正常营业 |

审核时长：通常 **1~3 个工作日**。

### 5.5 应用接入全流程（6 步）

**第 1 步：申请成为开发者**（详见第三篇）

**第 2 步：申请"商家后台系统"类目资质**

路径：`账号管理 -> 资质信息 -> 申请类目资质 -> 电商后台应用 -> 商家后台系统`

**第 3 步：创建应用**

路径：`应用管理 -> 应用中心 -> 新建应用 -> 电商后台应用 -> 商家后台系统`

注意：`app_id` 与 `appkey` 常作为同概念使用（值相同）。

**第 4 步：商家授权（关键步骤）**

1. 商家准备 shop_id：商家后台 `店铺设置 -> 基本信息`
2. 开发者提交店铺授权：`应用管理 -> 应用详情 -> 授权管理 -> 添加店铺授权`
3. 商家开启授权开关：商家后台 `店铺 -> 店铺管理 -> 服务授权`

授权审核规则：

- 主体一致：通常自动通过
- 主体不一致：人工审核，需天眼查/企查查截图，1~3 个工作日

授权状态说明：

| 状态 | 含义 |
|---|---|
| 待审核 | 平台审核中 |
| 待授权 | 审核通过，待商家开启开关 |
| 审核驳回 | 审核不通过 |
| 已解除 | 商家关闭授权，接口不可调用 |
| 已授权 | 授权生效，可调用接口 |

**第 5 步：获取 access_token**

推荐两种方式：

1. SDK 获取（推荐，已封装签名逻辑）
2. 接口方式（`/token/create` 与 `/token/refresh`）

**第 6 步：业务场景对接**

- 店铺与素材中心
- 商品、订单与库存
- 售后退款、物流发货与电子面单
- 账单对账
- 精选联盟、保险与商户登录风险
- 飞鸽客服与短视频管理

### 5.6 access_token 规则速查

- 默认有效期：**7 天**
- `app_id : shop_id = 1:N`（一个应用可多店）
- `shop_id : access_token = 1:1`
- `app_id + shop_id` 唯一确定一个 access_token

**SDK 方式：**

```java
GlobalConfig.initAppKey("xxxxxxxxxx");
GlobalConfig.initAppSecret("xxxxxxxxxx");
AccessToken accessToken = AccessTokenBuilder.build(123456L);
```

**接口方式（/token/create）：**

```text
https://openapi-fxg.jinritemai.com/token/create?app_key=xxx&method=token.create&param_json={"code":"","grant_type":"authorization_self","shop_id":"12312312"}&timestamp=2021-07-02 10:47:32&v=2&sign=your_sign
```

注意点：

- `grant_type=authorization_self` 时，`code` 传空字符串即可
- 建议始终传 `shop_id`；不传时默认返回最早授权店铺 token
- 到期前 >1h 调用：返回原 token
- 到期前 <=1h 调用：返回新 token，原 token 再保留约 1 小时
- 过期后调用：返回新 token，原 token 失效
- 建议本地缓存 token，到期前 1 小时刷新

### 5.7 常见问题（FAQ）

**Q1：可以创建多个应用吗？**
不可以。该类目下仅支持 1 个应用。多店铺请走授权流程。

**Q2：主体不一致怎么办？**
需证明强关联关系（同法人/母子公司/控股），提交天眼查或企查查截图。

**Q3：可以上服务市场吗？**
不可以。仅限商家自用。

**Q4：接口权限和可对接场景怎么查？**
查看《应用类目权限指引》与《场景对接方案》。

**Q5：如何查询已有 access_token？**
通过官方 token 查询工具查询。

### 5.8 失败高风险点

1. 软著主体与开发者主体不一致，且无强关联证明
2. 未在说明书中写清 API 调用信息和系统架构
3. 授权店铺状态异常（非正常营业）
4. 未传 `shop_id` 导致拿到非目标店铺 token
5. token 过期策略未处理，线上调用间歇性报错
6. 软著非国家版权局颁发，或只提供易版权等第三方电子版权认证
7. 软著不是电商 OMS/ERP/WMS/CRM 等管理系统类，例如游戏、天气等普通 APP
8. 著作权人、登记号与证书图片信息不一致，或存在 PS/造假痕迹
9. 未提供商家研发系统支出证明，或支出截图/合同文件无法体现公司主体信息

### 5.9 使用建议

- 先准备材料再发起资质，减少驳回往返
- 14 类必申请 API 一次性完整申请；短信 API 不申请；工具 API 不作为业务权限整包申请
- 上线前核对收费接口名单，完成预充值、调用量预算和余额预警
- 先完成 1 家店全链路打通（资质→应用→授权→token→业务接口），再扩展多店
- 生产环境实现 token 缓存与续期机制（建议到期前 1 小时刷新）
- 留存审核与授权截图，便于后续复核与异常申诉

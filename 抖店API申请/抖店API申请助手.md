# 抖店API申请助手（自用型应用：商家后台系统）

更新时间：2024-10-25 14:37:01  
文档用途：用于商家自研系统申请抖店开放平台 API 能力，覆盖入驻标准、材料准备、授权流程、Token 获取与常见问题。

> 2026-07-14 实际申请已因绑定店铺非官方旗舰店被驳回。完整结果、凭证与复盘见 [`申请助手.md` 第六篇](./申请助手.md#第六篇-友联实际申请记录与经验)。

---

## 1. 适用范围与核心限制

- 仅适用于**商家后台系统（自用型应用）**，只能给商家自有店铺使用。
- 应用不可提供给他人店铺，不可在服务市场发布服务。
- APPKEY / app_id 不可转让给他人使用。
- 同一公司主体仅可创建 **1 个**商家后台系统应用。
- 如同集团多店铺使用，需走多店铺绑定授权流程。

---

## 2. 申请前自检（必须全部满足）

### 2.1 主体一致性

以下三者原则上需一致；若不一致，需提供强关联证明（天眼查/企查查）：

1. 软件著作权主体  
2. 开发者账号认证主体  
3. 授权店铺主体

### 2.2 开发能力与证明材料

必须具备自研能力并可提交：

- 国家软件著作权证书（截图）
- 系统功能说明书（含 API 调用信息、系统架构说明、功能截图、源代码片段）
- 授权店铺信息（正常营业状态）

---

## 3. 材料清单（提交类目资质时）

| 材料 | 要求 |
|---|---|
| 系统功能说明书 | 必须体现调用 API 信息、系统架构、功能截图、软著、源代码片段 |
| 软件著作权 | 电商应用软著截图；主体需匹配或可证明强关联 |
| 绑定店铺 | 填写授权店铺名称，店铺需正常营业 |

审核时长：通常 **1~3 个工作日**。

---

## 4. 应用接入全流程（6步）

## 4.1 申请成为开发者

按抖店开发者入驻流程先完成开发者注册。

## 4.2 申请“商家后台系统”类目资质

路径：`账号管理 -> 资质信息 -> 申请类目资质 -> 电商后台应用 -> 商家后台系统`

## 4.3 创建应用

路径：`应用管理 -> 应用中心 -> 新建应用 -> 电商后台应用 -> 商家后台系统`

注意：对接过程中 `app_id` 与 `appkey` 常作为同概念使用（值相同）。

## 4.4 商家授权（关键步骤）

### 4.4.1 商家准备 shop_id

商家后台路径：`店铺设置 -> 基本信息`

### 4.4.2 开发者提交店铺授权申请

开放平台路径：`应用管理 -> 应用中心 -> 应用详情 -> 授权管理 -> 添加店铺授权`

授权审核规则：

- **主体一致**：通常自动审核通过
- **主体不一致**：进入人工审核，需提交天眼查/企查查强关联截图，时长 1~3 个工作日

授权状态说明：

- `待审核`：平台审核中
- `待授权`：审核通过，待商家开启授权开关
- `审核驳回`：审核不通过
- `已解除`：商家关闭授权，接口不可调用
- `已授权`：授权生效，可调用接口

### 4.4.3 商家开启授权开关

商家后台路径：`店铺 -> 店铺管理 -> 服务授权`  
将目标应用开关打开后，开发者侧授权记录应显示为 `已授权`。

## 4.5 获取 access_token

商家完成授权后，大多数接口调用需传 `access_token`。

推荐两种方式：

1. SDK 获取（推荐）  
2. 直接调用 `/token/create` 与 `/token/refresh`

---

## 5. access_token 规则速查

- 默认有效期：**7天**
- `app_id : shop_id = 1:N`
- `shop_id : access_token = 1:1`
- `app_id + shop_id` 可唯一确定一个 access_token

### 5.1 SDK方式（推荐）

优势：SDK 已封装签名逻辑，减少签名错误风险。

```java
// 全局初始化
GlobalConfig.initAppKey("xxxxxxxxxx");
GlobalConfig.initAppSecret("xxxxxxxxxx");

// 通过 shopId 获取 access_token
AccessToken accessToken = AccessTokenBuilder.build(123456L);
```

### 5.2 接口方式（/token/create）

请求示例：

```text
https://openapi-fxg.jinritemai.com/token/create?app_key=xxx&method=token.create&param_json={"code":"","grant_type":"authorization_self","shop_id":"12312312"}&timestamp=2021-07-02 10:47:32&v=2&sign=your_sign
```

注意点：

- `grant_type=authorization_self` 时，`code` 可传空字符串 `""`
- 自用型应用支持多店授权，建议始终传 `shop_id`；不传时默认返回最早授权店铺 token
- 在 token 到期前 >1h 调用：通常返回原 token（有效期不变）
- 在 token 到期前 <=1h 调用：返回新 token，原 token 再保留约 1 小时
- 过期后调用：返回新 token，原 token 失效
- 建议本地缓存 token，不要每次接口调用前都重新申请

## 6. API 能力申请与业务对接入口

完整清单见：[`抖店API能力申请清单.md`](./抖店API能力申请清单.md)
具体接口文档见：[`具体接口文档/README.md`](./具体接口文档/README.md)（16 类、506 个接口）
收费规则见：[`抖店API收费规则.md`](./抖店API收费规则.md)

| 申请层级 | API 类别 | 处理方式 |
|---|---|---|
| 核心业务申请范围 | 店铺、素材中心、商品、订单、库存、售后退款、物流发货、电子面单、账单 | 本次全部申请；具体收费以接口级名单为准 |
| 专项业务申请范围 | 精选联盟、保险、商户登录风险、飞鸽、短视频 | 本次全部申请；商户登录风险对应风控安全 API 下的 `/antispam/userLogin` |
| 明确排除 | 短信 API | 本次不申请 |
| 工具 API 目录 | 权益、服务市场、授权/Token 等通用工具 | 原则上不作为业务权限申请；Token、授权查询等必要接入能力保留 |
| 其他专项 API | 三方客服、即时零售、电商小程序、跨境等 | 有明确业务需求后单独评估 |

完成授权和 token 后，依次打通店铺与素材、商品、订单、库存、售后退款、物流发货、电子面单、账单，以及精选联盟、保险、商户登录风险、飞鸽和短视频能力；不接入短信 API。

收费提示：基础收费 API 云内/云外价格分别为 0.018/0.18 元每百次每 Appkey；增值收费 API 分别为 0.05/0.5 元。平台采用预充值模式，需配置余额和欠费预警。

## 7. 常见问题（FAQ）

### Q1：已通过“商家后台系统”资质，可以创建多个应用吗？
不可以。该类目下仅支持创建 1 个应用。多店铺请走店铺授权流程。

### Q2：主体不一致怎么办？
需证明强关联关系（同法人/母子公司/控股关系等），提交天眼查或企查查截图。

### Q3：商家后台系统应用可以上服务市场吗？
不可以。仅限商家自用。

### Q4：接口权限和可对接场景怎么查？
查看《应用类目权限指引》与《场景对接方案》。

### Q5：如何查询已有商家授权的 access_token？
通过官方 token 查询工具查询已有授权信息。

---

## 8. 失败高风险点（建议重点排查）

1. 软著主体与开发者主体不一致，且无强关联证明  
2. 未在说明书中写清 API 调用信息和系统架构  
3. 授权店铺状态异常（非正常营业）  
4. 未传 `shop_id` 导致拿到非目标店铺 token  
5. token 过期策略未处理，线上调用间歇性报错

---

## 9. 使用建议（落地版）

- 先准备材料再发起资质，减少驳回往返。
- 14 类必申请 API 一次性完整申请；短信 API 不申请；工具 API 不作为业务权限整包申请。
- 上线前核对收费接口名单并完成预充值、调用量预算和余额预警。
- 先完成 1 家店全链路打通（资质->应用->授权->token->业务接口），再扩展多店。
- 生产环境实现 token 缓存与续期机制（建议到期前 1 小时刷新）。
- 留存审核与授权截图，便于后续复核与异常申诉。
